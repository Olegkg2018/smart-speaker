# Happy Speaker — домашняя умная колонка

Голосовой ассистент на русском языке: свободный разговор, музыка, погода,
новости, таймеры. ESP32-S3 работает тонким клиентом, вся логика — на домашнем
сервере.

```
ESP32-S3 N16R8                    Сервер (S905X3, Armbian)
┌────────────────┐                ┌──────────────────────────────────┐
│ микрофон (I2S0)│ ───PCM 16k──▶  │ WS /stream                       │
│ кнопка   (GPIO)│ ───ptt──────▶  │   ├─ STT: faster-whisper (ru)     │
│ усилитель(I2S1)│ ◀──PCM 48k───  │   ├─ Agent: Claude Opus 5 + tools │
│ OLED 0.96"     │ ◀──битмап────  │   ├─ TTS: Piper (ru)              │
│ светодиод      │ ◀──state─────  │   ├─ AudioMixer: музыка + речь    │
└────────────────┘                │   └─ Screen: картинка для OLED    │
                                  └──────────────────────────────────┘
```

Схема выше — путь по умолчанию (`VOICE_PROVIDER=claude`). Есть второй,
переключаемый: [голосовой бэкенд](#голосовой-бэкенд).

Два решения определяют всё остальное:

**Весь звук микшируется на сервере.** Колонка получает один готовый поток и
просто отдаёт его в усилитель. Поэтому речь звучит поверх музыки с
автоматическим приглушением (ducking), а прошивку не нужно трогать при
изменении логики.

**Картинку для экрана тоже рисует сервер** и присылает готовым битмапом
(1024 байта на кадр). В прошивке нет ни шрифтов, ни рендеринга — зато на
экране полноценная кириллица любым системным шрифтом.

## Сервер: S905X3 на Armbian

Четыре ядра Cortex-A55 без AVX — это накладывает ограничения, о которых стоит
знать заранее.

**Распознавание — узкое место.** Замер на живом железе (`tools/bench.py`):

| Модель | Время на фразу | Качество на бытовых репликах |
|---|---|---|
| `base` | 4.6–5.0 с | ошибается терпимо |
| `tiny` | 2.6 с | путает слова заметно |

Время почти не зависит от длины реплики — Whisper всегда считает окно в
тридцать секунд, и на Cortex-A55 один только энкодер стоит несколько секунд.
Меньше двух секунд от этой архитектуры на такой плате не добиться.

Это ломает бюджет задержки: обещанные полторы секунды до первого звука
превращаются в пять-шесть. Варианты, если пауза окажется неприемлемой:

- **Vosk** — потоковый распознаватель, считает *пока вы говорите*, поэтому
  результат готов почти сразу после отпускания кнопки. Модель на русском
  весит 45 МБ, на ARM работает быстрее реального времени. Тоже локальный,
  приватность не страдает. Потребует переписать `app/stt.py`.
- **whisper.cpp** вместо ctranslate2 — те же тридцать секунд окна, но лучше
  оптимизирован под NEON; ожидаемо в полтора-два раза быстрее.
- **Оставить `base`** и смириться с паузой в пять секунд.

**Установка** проходит без сборки из исходников: `ctranslate2` (движок
faster-whisper) и `piper-tts` выкладывают готовые колёса под aarch64 —
проверено на этой плате. Компилировать ничего не придётся.

**Синтез и микширование** упираются в проценты одного ядра — тут запаса
достаточно. LLM живёт в облаке, так что 4 ГБ памяти хватает с большим избытком.

## Запуск в Docker (так стоит на сервере)

```bash
cd server
cp .env.example .env      # вписать ANTHROPIC_API_KEY, проверить HAPPY_MUSIC_DIR
docker compose up -d --build
docker compose logs -f
```

Первый старт занимает несколько минут: контейнер докачивает голос Piper
(~60 МБ) и веса whisper. Оба лежат в томе `models` и переживают пересборку
образа — дальше сервер стартует за десятки секунд.

Порт наружу — `HAPPY_PORT` (по умолчанию 8090, потому что 8080 на сервере
занят). Внутри контейнера всегда 8080. Фонотека подключается только на чтение
из `HAPPY_MUSIC_DIR`.

Проверка: `curl localhost:8090/health`, адрес для колонки —
`ws://<сервер>:8090/stream`.

Замер скорости на живом железе:

```bash
docker compose exec happy python tools/bench.py
```

Синтезирует три бытовые фразы и распознаёт их обратно, показывая RTF. Больше
единицы — распознавание не успевает за речью, и после каждой фразы будет
пауза; тогда стоит взять модель поменьше.

## Что нужно поставить (без Docker)

```bash
sudo apt install ffmpeg python3-venv fonts-dejavu-core
pip install yt-dlp
```

`ffmpeg` декодирует всё подряд в PCM для микшера; без него не будет музыки,
остальное — будет. `fonts-dejavu-core` даёт шрифт для экрана колонки; без него
экран просто отключится, сервер продолжит работать.

## Установка сервера

```bash
cd server
python3 -m venv .venv && source .venv/bin/activate
pip install -e .

# Голос синтеза (~60 МБ)
python -m piper.download_voices ru_RU-irina-medium --data-dir models

cp .env.example .env    # и вписать ANTHROPIC_API_KEY
```

Модель распознавания скачается сама при первом запуске (~500 МБ для `small`).

## Запуск

```bash
cd server
python -m app.main
```

Первый старт занимает полминуты — грузятся модели. Дальше сервер держит их
в памяти, чтобы первый же вопрос не ждал загрузки.

Проверка живости: `curl localhost:8080/health`.

## Проверка без железа

Пока прошивка не залита, колонку изображает ноутбук:

```bash
pip install sounddevice websockets
python tools/pc_client.py ws://localhost:8080/stream
```

Enter — начать говорить, Enter ещё раз — закончить.

## Прошивка

Нужен ESP-IDF v5.1+.

```bash
cd firmware
idf.py set-target esp32s3
idf.py menuconfig      # раздел «Happy Speaker»: Wi-Fi, адрес сервера, пины
idf.py flash monitor
```

Распиновка по умолчанию — стандартная схема плат Xiaozhi ESP32-S3 N16R8
с OLED 0.96". Всё паяно на плате, ничего подключать не нужно:

| Узел | Сигналы | GPIO |
|---|---|---|
| Микрофон INMP441 | WS / SCK / SD | 4 / 5 / 6 |
| Усилитель MAX98357A | LRC / BCLK / DIN | 16 / 15 / 7 |
| OLED SSD1306 | SDA / SCL | 41 / 42 (адрес 0x3C) |
| Кнопка разговора | BOOT | 0 |
| Громкость | тише / громче | 39 / 40 |
| Светодиод WS2812 | DIN | 48 |

Если ваша ревизия отличается — всё правится в `menuconfig`, раздел
«Happy Speaker → Распиновка», перепаивать ничего не придётся.

Экран и светодиод необязательны: не отвечает контроллер по 0x3C — прошивка
скажет об этом в лог и продолжит без экрана.

Разговор начинается двумя способами: активационным словом («Компьютер») или
тапом по кнопке. Кнопка работает тапом, а не удержанием: одно нажатие
начинает слушать, конец реплики находит сервер сам — по тишине (см.
«Настройки», `VAD_*`). Повторный тап во время прослушивания досрочно
останавливает запись; тап во время ответа перебивает ассистента.

Светодиод показывает состояние цветом:

| Цвет | Что значит |
|---|---|
| Красный, частое мигание | нет связи с сервером |
| Зелёный, ровно | слушает |
| Синий, мигает | думает |
| Голубой, медленно | говорит |
| Тусклый сиреневый | играет музыка |
| Погашен | ждёт нажатия |

## Протокол

Один WebSocket. Бинарные фреймы — аудио, текстовые — управление.

Бинарный фрейм: первый байт — тип, дальше полезная нагрузка.

| Тип | Направление | Содержимое |
|---|---|---|
| `0x01` | колонка → сервер | PCM 16 кГц, кадр 20 мс |
| `0x02` | сервер → колонка | PCM 48 кГц, кадр 20 мс |
| `0x03` | сервер → колонка | кадр экрана, 1024 байта в раскладке SSD1306 |

```json
→ {"t": "hello", "device": "kitchen", "fw": "0.1.0", "codec": "pcm", "screen": true}
→ {"t": "ptt", "state": "down"}      // тап: начать слушать, либо (если уже
                                      // слушаем) досрочно остановить запись
→ {"t": "volume_step", "value": 0.1} // кнопка громкости: сдвиг, не значение
← {"t": "ready", "codec": "pcm"}     // фактически выбранный кодек
← {"t": "state", "value": "listening|thinking|speaking|playing|idle"}
```

Клиент не принимает решений сам — сервер решает, что означает тап (начать
или остановить), и когда реплика закончилась (по тишине); колонка только
сообщает о кнопке, включает микрофон по своему состоянию `listening` и
играет то, что пришло. `"ptt"` `"up"` от старых версий прошивки сервер
просто игнорирует.

## Настройки

Всё в `server/.env` (образец — `.env.example`). Что менять чаще всего:

- `WHISPER_MODEL` — `base` быстрее, `small` точнее на русском, `medium` ещё
  точнее, но вдвое медленнее.
- `EFFORT` — глубина рассуждений модели. Для голоса `low`: разговор важнее
  выкладок. Мышление при этом **остаётся включённым** — с выключенным Opus 5
  иногда пишет вызов инструмента обычным текстом, и он молча не срабатывает.
- `DEFAULT_CITY` и координаты — для погоды без уточнения города.
- `VAD_THRESHOLD` — порог амплитуды, которым детектор тишины отличает речь
  от фона. В шумной кухне стоит поднять; если колонка обрезает тихие
  реплики — понизить. `VAD_SILENCE_MS` — сколько подряд тишины считается
  концом фразы (по умолчанию 900 мс).

## Активация голосом

Пока активационное слово не прозвучало, звук **не покидает дом**: колонка
шлёт микрофон на сервер по локальной сети, а сервер ищет слово у себя,
моделью Vosk. В облако — и в счёт — попадает только то, что сказано после
активации. Кнопка при этом продолжает работать.

```bash
# Модель кладётся в том models, рядом с голосом Piper:
curl -LO https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip
unzip vosk-model-small-ru-0.22.zip
docker run --rm -v server_models:/m -v "$PWD":/src alpine \
  sh -c "cp -r /src/vosk-model-small-ru-0.22 /m/vosk-ru && chown -R 1000:1000 /m/vosk-ru"
```

Затем `WAKE_WORD_ENABLED=true` в `.env`.

**Слово стоит выбирать подлиннее.** Замер на синтезированной речи:

| Слово | Ловит | Ложные срабатывания |
|---|---|---|
| «Компьютер» | 2/2 | 0 |
| «Алиса» | 2/2 | «Лариса», «Мелисса», «лиса» |
| «Джарвис» | 2/2 | «сервис», «джаз» |

Короткие слова распознаватель притягивает к себе по созвучию, и колонка
просыпается зря — а каждое ложное пробуждение уходит в облако за деньги.
Если короткое слово всё же нужно, перечислите созвучия в
`WAKE_WORD_NEIGHBOURS`: ложные срабатывания падают втрое, но появляются
пропуски (в замере — 2 попадания из 3 вместо 3 из 3).

Цена на S905X3 — примерно треть одного ядра и 215 МБ памяти постоянно.
Распознавание идёт пачками по 200 мс в отдельном потоке: если считать каждый
кадр прямо в цикле событий, WebSocket перестаёт успевать с пингами и связь
с колонкой рвётся каждые несколько секунд.

## Голосовой бэкенд

Два взаимозаменяемых пути `app/voice.py` / `app/realtime.py`, переключаются
`VOICE_PROVIDER` в `.env` без изменений в прошивке и протоколе — колонка не
знает, кто отвечает.

**`claude` (по умолчанию).** Whisper → Claude Opus 5 с инструментами → Piper.
Работает целиком локально, кроме самой языковой модели. Платите только за
токены Claude. Плата за это — распознавание: Whisper на S905X3 всегда
считает тридцатисекундное окно, поэтому первый звук приходит через пять-шесть
секунд после отпускания кнопки (подробности — в разделе про S905X3 выше).

**`openai_realtime`.** Спич-ту-спич через OpenAI Realtime API: аудио с
микрофона уходит в модель потоком и возвращается уже готовой речью — ни
Whisper, ни Piper не участвуют, оба даже не загружаются на старте. Убирает
паузу на распознавание и роботизированность Piper разом, ценой более дорогого
и полностью облачного пути. Кнопка на колонке по-прежнему решает, когда
слушать и когда просить ответ — серверный VAD в сессии выключен нарочно.

```
# .env
VOICE_PROVIDER=openai_realtime
OPENAI_API_KEY=sk-...
OPENAI_REALTIME_MODEL=gpt-realtime   # голоса marin и cedar — только на нём
OPENAI_VOICE=marin
```

Инструменты (музыка, погода, таймеры, новости) объявлены один раз в
`app/tools/registry.py` и работают одинаково в обоих бэкендах — переключение
провайдера их не касается.

Не проверено вживую: нужен `OPENAI_API_KEY`, которого пока нет ни в одном
`.env`. Код собран и задеплоен, но диалог через Realtime ни разу не прогонялся
на живом железе.

## Как устроен ответ

Ощущаемая скорость держится на том, что колонка не ждёт полного ответа модели:

1. Ответ Claude стримится по токенам.
2. `SentenceBuffer` собирает их до конца предложения.
3. Готовое предложение сразу уходит в Piper и дальше в микшер.

Первый звук идёт примерно через полторы секунды после конца речи, а не через
три-четыре.

## Тесты

```bash
cd server && python -m pytest
```

Покрыты микшер (ducking, клиппинг, границы кадров), нарезка на предложения,
пересчёт частоты, склонение времени вслух и отрисовка экрана с кириллицей.

## Состояние

Готово и проверено тестами: микшер, разбиение на предложения, ресемплинг,
русские числительные, рендер экрана.

Написано, но требует живого прогона с ключом API и моделями: распознавание,
синтез, агент с инструментами, воспроизведение музыки, прошивка.

Проверено на целевом железе (S905X3, $HAPPY_HOST:8090): образ собирается,
сервер стартует, модели грузятся, локальная фонотека на 2399 файлов видна,
ffmpeg и yt-dlp на месте. Протокол проверен целиком: подключение, кнопка
громкости, цикл состояний, кадры экрана.

Не проверено вживую: ответ модели и музыка — нужен `ANTHROPIC_API_KEY`
в `server/.env`, сейчас там пусто (сервер стартует и предупреждает об этом).

Второй голосовой бэкенд (`VOICE_PROVIDER=openai_realtime`, спич-ту-спич
через OpenAI) написан, задеплоен, собирается в образ — но ни разу не
прогонялся с живым `OPENAI_API_KEY`, которого тоже пока нигде нет. Подробнее
в разделе «Голосовой бэкенд» выше.

Главная открытая проблема на пути `claude`: пауза распознавания в пять
секунд (см. выше) — второй бэкенд для того и существует, чтобы её убрать.

В планах:

- **Wake word** вместо кнопки — детекция на сервере (openWakeWord), колонка
  стримит постоянно. Кнопка останется запасным входом.
- **Эхоподавление**: при громкой музыке микрофон слышит колонку. Сейчас
  спасает push-to-talk, для wake word понадобится AEC.
- **Opus** вместо PCM: трафик упадёт примерно в пятнадцать раз. Серверная
  часть уже готова (`app/audio/codec.py`), нужен кодек в прошивке.
